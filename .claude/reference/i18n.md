# Internationalization (next-intl)

Locales: `ko`, `en`, `zh-TW`. Default `en`. `localePrefix: "always"` — every URL carries a
locale segment. Configured in `src/i18n/routing.ts`; wired into the build by
`createNextIntlPlugin()` in `next.config.ts`.

## Files

- `src/i18n/routing.ts` — locale list / default / prefix. `localeDetection: false`;
  detection lives in `src/middleware.ts` (see architecture.md).
- `src/i18n/request.ts` — server request config, dynamically imports
  `./messages/{locale}.json`.
- `src/i18n/navigation.ts` — locale-aware `Link`, `redirect`, `usePathname`, `useRouter`,
  `getPathname`. Prefer these over `next/link` for internal navigation; note that
  `header.tsx` and `LanguageSupport.tsx` currently use plain `next/link` with explicit
  locale hrefs.
- `src/i18n/messages/{ko,en,zh-TW}.json` — nested namespaces (`common`, `info`, `contact`, …).

## Working with copy

- A new string means editing **all three** message files with the same key path. A key
  missing from one locale throws at render time in that locale.
- Server/client components: `useTranslations("namespace")` then `t("key")`.
- `src/components/Trans.tsx` is the convenience wrapper: `<Trans id="key" ns="namespace" />`
  renders a `<span>`; it also takes `values` for ICU interpolation and `className`.
- Never concatenate translated fragments in JSX — put the whole sentence in the message
  file (existing copy uses `line1` / `line2` style keys for multi-paragraph blocks).
- `.vscode/settings.json` points i18n-ally at `src/i18n` and `src/i18n/messages`.

## Language switcher

`src/app/[locale]/components/LanguageSupport.tsx` holds the display-name map
(`ko: 한국어`, `en: English`, `zh-TW: 繁體中文`). Adding a locale means touching
`routing.ts`, the middleware's `Accept-Language` branch, a new messages file, and this map.
